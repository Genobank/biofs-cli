What run 1 showed that bears on this amendment: in pair D3 (three baseline nodules, LesionLocator tracker) the 20 mm nodule was reported "resolved" and the 16 mm nodule
took the follow-up of the first one ("shrunk", 17.7 to 11.7 mm). The tracked mask file held a single label (1), located on the follow-up of the 20 mm nodule; the executor read
the label under each baseline instance id, so with more than one baseline lesion an id was matched to whatever the mask held under that number. With one baseline lesion (D2) it
works by coincidence. Cause found by reading the masks on the VM, not guessed.

Change: findings_runner.py now tracks every baseline lesion with its own call and its own binary prompt (lesionlocator_track_each), so the label of each tracked mask is the
baseline instance id by construction; a failed call sends every lesion to the overlap fallback. Backup of the previous file: findings_runner.py.bkp.pre_trackeach_20261105_141125.
Unit test test_findings_tracking.py (a fake tracker that behaves as the real one did) fails on the previous code and passes on the new.
