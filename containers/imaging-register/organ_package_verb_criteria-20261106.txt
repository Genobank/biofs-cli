Interface contract
  CLI to node
    POST {BASE}/submit_organ_package  body {wallet, signature, register_job_id, organs, floors}; organs is the string "default" (or absent) or an array of organ names; floors is a boolean, default true.
      202 {package_job_id, status: "running", register_job_id, organs, floors, gate_verdict}
    GET  {BASE}/organ_package_status?package_job_id=<id>  header x-biofs-signature (or query signature)  200 the job row.
    Ids: register-<uuid> for the input, package-<uuid> for the job. biocid of the result: biocid://genobank/<wallet lowercase>/imaging-organ-package/<package_job_id>, parent biocid://genobank/<wallet lowercase>/imaging-register/<register_job_id>.
  node to executor (same port 8787 as imaging_register)
    POST http://<ip>:8787/agent/organ_package  body {wallet, job_id, register_job_id, input_gcs, organs, floors}; answer 200 {status: "running"}.
    GET  http://<ip>:8787/agent/organ_package_status?job_id=<package_job_id>  answer {status: running|done|error, exit_code, result}.
    result on done: {schema: "organ-twin-package/1", output_gcs, files, bytes, verify: {ok}, floors_sha256 or null, built_at}; on error: {error}.
    input_gcs = gs://genobank-health-imaging/<wallet>/imaging-register/<register_job_id>, output_gcs = gs://genobank-health-imaging/<wallet>/imaging-organ-package/<package_job_id>.
    The executor must refuse an input_gcs whose wallet segment is not the wallet in the request, and must run organ_package.py build with --floors only when floors is true.

  ON2 ownership and state. Unknown register job 404. A register job of another wallet 403 with an answer that carries only the error text. A register job whose status is not done 409 naming the status.
      A done job whose gate verdict is FAIL is accepted (the abdomen jobs of Nov 5 were FAIL and still yield a rigid-frame package), and the verdict is stored on the package job row as gate_verdict.
  ON3 dispatch. The executor receives exactly {wallet, job_id, register_job_id, input_gcs, organs, floors}. input_gcs is built from the signer's wallet and the register job id; a different output_gcs
      stored in the register row is ignored (a test row carries one). The row stores wallet, register_job_id, organs, floors, executor name and ip, status running, created_at, and no signature.
      Executor refusal or network failure: the row becomes error with the message and the answer is 502 with the package_job_id. No executor available: 503 and no row. A second submit for the same
      register job while a package job of the same wallet is running: 409 naming the running job.
  ON4 status. Unknown id 404; malformed id 400; no signature 401; another wallet 403. A running job is polled once at the executor. On done: the row becomes done with the result, the biocid is registered

      gcs_path <wallet>/imaging-organ-package/<id>, derived_from [the register biocid], consent_status active) and in bioroutes.inventory (hierarchy_role derived, hierarchy_parents the same list,
      owner_wallet the signer). A second status call after done does not touch the registry. On executor error: row error with the executor's message. Executor unreachable: the current row, unchanged.
      A row that is already done is returned without calling the executor. The biocid is registered only after the executor reported done and only when result.verify.ok is true; a done result with
      verify.ok false makes the row error with the reason "package failed its own verify" and registers nothing.
